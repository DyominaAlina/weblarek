# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get<T>(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post<T>(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные:
### interface Product
Массив данных. Содержит информацию о товаре, из которой составляем массивы каталога товаров на главной странице, передаем в карточку товара и в корзину.
`id: string` - уникальный идентификатор товара.
`tital: string` - название товара.
`image: string` - изображение товара.
`category: string` категория товара.
`price: number | null` - цена товара.
`description: string` - описание товара.

### interface Customer
Массив данных. Содержит информацию о покупателе, необходимую для оформления заказа.  
`payment: 'cash'|'card'|''` - способ оплаты, возможен выбор из 2 значений, а также может быть пустым (не выбран ни один из вариантов).
`address: sring` - адрес доставки.
`email: sring` - email покупателя.
`phone: sring` - номер телефона покупателя.

### Тип ApiProductListResponse
Описывает ответ сервера со списком товаров.

`total: number` — общее количество товаров.
`items: Product[]` — массив товаров.

### Тип OrderRequest
Описывает данные заказа, отправляемые на сервер.

`поля интерфейса Customer`
`items: string[]` — массив идентификаторов товаров
`total: number` — итоговая сумма заказа

### Тип OrderResponse
Описывает ответ сервера после оформления заказа.

`id: string` — идентификатор заказа.
`total: number` — итоговая сумма заказа.

### Тип ValidationErrors
Объект с текстами ошибок валидации полей формы.

## Модель данных
### Класс Catalog
Позволяет сохранять и получать массив товаров и выбранную карточку товара.

Конструктор:  
`constructor(events: IEvents, productList: Product[] = [], product: Product)` - конструктор получает на вход события, массив объектов (товаров) и отдельный объект (товар).

Поля класса:  
`events: IEvents` — брокер событий.
`productList: Product[]` -  массив всех товаров с типом Product.
`product: Product` - выбранный для подробного отображения товар с типом Product.

Методы:  
`getCard(): Product | null` - получение товара для подробного отображения.
`saveCard(product: Product):void` - сохранение товара для подробного отображения.
`getProduct(id: string): Product | undefined` -  получение одного товара по его id.
`getProductList(): Product[]` - получение массива товаров из модели.
`saveProductList(products: Product[]):void` - сохранение массива товаров полученного в параметрах метода.

События модели:
`catalog:changed` — каталог товаров изменён.  
`catalog:card-changed` — изменён выбранный товар.

### Класс Cart
Хранит массив товаров, выбранных покупателем для покупки.Позволяет получать список товаров, управлять перемещением товаров (добавление и удаление товаров) в/из корзины, рассчитывать количество товаров в корзине и их общую стоимость, определять наличие товара в корзине.

Конструктор:  
`constructor(events: IEvents, selectedProducts: Product[] = [])` - конструктор получает на вход события, массив товаров, выбранных покупателем для покупки (добавленных в корзину).

Поля класса:  
`events: IEvents` — брокер событий.  
`selectedProducts: Product[]` - массив товаров, добавленных в корзину с типом Product

Методы:  
`getProductsList(): Product[]` - Получение массива товаров, добавленных (находящихся) в корзину.
`addProduct(product: Product):void` - добавление товара, который был получен в параметре, в массив корзины.
`deleteProduct(id:string):void` - удаление товара, полученного в параметре, из массива корзины.
`getCountProducts():number` - счетчик количества товаров в корзине, получение количества товаров в корзине.
`getCostProducts():number` - получение общей суммы стоимости всех товаров в корзине.
`isAdded(id: string):boolean` - определение (проверка) наличия товара в корзине по его id, полученного в параметр метода.
`cleanCart():void` - очистка корзины.

События модели:
`cart:changed` — содержимое корзины изменено.

### Класс Purchase
Хранит вид оплаты, адрес доставки, телефон и почту покупателя. Позволяет получать, сохранять и проверять данные о покупателе.

Конструктор:  
`constructor(events: IEvents, purchase: Customer = {payment: '', address: '', email: '', phone: ''})` - Конструкор получает на вход события, объект с данными о покупателе с типом Customer.

Поля класса:  
`events: IEvents` — брокер событий.  
`purchase: Customer` - объект Покупатель с типом Customer.

Методы:  
`getPurchase(): Customer` - получение всех данных о покупателе.
`savePurchase(data: Customer):void` - сохранение данных о покупателе в модели и генерация события изменения формы.
`verificationPurchase():void` - валидация данных с предоставлением информации об ошибке, связанной с проверкой конкретного значения. Возвращает объект ошибок.
`cleaningPurchase():void` - очистка данных покупателя и генерация события изменения.

События модели:
`purchase:changed` — данные покупателя изменены.


## Слой коммуникации
Отвечает за взаимодействие приложения с внешним сервером.  
Инкапсулирует логику получения и отправки данных и не содержит бизнес-логики интерфейса. 

### Класс StoreApi
Класс коммуникационного слоя. Отвечает за взаимодействие приложения с сервером: получение массива товаров и отправку данных заказа.  
Использует композицию — в конструктор класса передаётся объект, реализующий интерфейс `IApi`, а внутри методов используются его методы `get` и `post`.

Конструктор:  
`constructor(api: IApi)` — конструктор принимает объект, реализующий интерфейс `IApi`, через который выполняются HTTP-запросы к серверу.

Поля класса:  
`api: IApi` — объект для выполнения запросов к серверу, реализующий методы `get` и `post`.

Методы:  
`getProductList(): Promise<ApiProductListResponse>` — получает массив товаров с сервера и преобразует поле `image` в полный URL с использованием `CDN_URL`. 
`createOrder(order: OrderRequest): Promise<OrderResponse>` — отправляет заказ на сервер.

`set total(value: number)` — устанавливает текст о списанной сумме.

## Слой Презентера
Презентер реализован в файле `src/main.ts` и не выделен в отдельный класс, так как приложение состоит из одной страницы, а основная координация логики удобно сосредоточена в точке входа. Создаёт экземпляры моделей, представлений, брокера событий и API-классов, а затем подписывается на события моделей и представлений. Пользовательские действия из интерфейса приводят к вызову методов моделей, модели изменяют состояние и генерируют события, а презентер обрабатывает эти события и обновляет отображение.

### События моделей
`catalog:changed` — получает массив товаров из модели каталога, создаёт карточки каталога и передаёт их в Gallery.
`catalog:card-changed` — получает выбранный товар из модели каталога и обновляет представление `CardDescription`.
`cart:changed` — обновляет счётчик в Header, содержимое и стоимость корзины в Basket, а также состояние кнопки в подробной карточке товара.
`purchase:changed` — обновляет данные, ошибки валидации и состояние кнопок сразу в обеих формах: FormOrder и FormContacts.

### События представлений
`card:select` — выбор карточки для просмотра.
`card:action` — нажатие кнопки покупки или удаления товара из подробной карточки.
`basket:open` — открытие корзины.
`cart:delete` — удаление товара из корзины.
`basket:submit` — переход к первому шагу оформления заказа.
`order.payment:change` — изменение способа оплаты.
`order.address:change` — изменение адреса доставки.
`order:submit` — переход ко второму шагу оформления заказа.
`contacts.email:change` — изменение email.
`contacts.phone:change` — изменение телефона.
`contacts:submit` — отправка заказа на сервер.
`success:close` — закрытие модального окна после успешного оформления заказа.
